## Gate 2 — create dedicated AI01 gateway account and protected configuration


## Gate 3 — provision Worker01 transport identity
Generate a dedicated SSH transport identity on Worker01. Keep the private half on Worker01.

```sh
ssh -i ~/.ssh/karmo_admin_ed25519 karmo@192.168.1.251 '

sudo install -d -o root -g karmo -m 0750 /etc/karmo/worker01
[ -e /etc/karmo/worker01/ssh_identity ] || ssh-keygen -q -t ed25519 -N "" -f /tmp/karmo-worker01-transport

cat /tmp/karmo-worker01-transport.pub
rm -f /tmp/karmo-worker01-transport /tmp/karmo-worker01-transport.pub

```

Capture only the public key output. On AI01, bind that exact public key to Worker01 using the forced command generated by Core:

```text
command="/usr/local/libexec/karmo-worker-gateway KARMO-WORKER01",restrict,no-agent-forwarding,no-port-forwarding,no-X11-forwarding,no-pty,no-user-rc <WORKER01_PUBLIC_KEY>
```

Install that single line as `/var/lib/karmo-gateway/.ssh/authorized_keys`, owned by root:root and mode `0644`. Do not add a normal unrestricted key for the gateway account.

## Rollback — Worker01 first
Stop scheduling and Worker01 before changing Core:

```sh
ssh -i ~/.ssh/karmo_admin_ed25519 karmo@192.168.1.251 'sudo systemctl disable --now karmo-worker01.service || true'
```

Revoke the Worker01 durable identity through the reviewed Core administrative path. Remove its forced-command authorized-key entry from AI01. Do not delete worker events, tickets, results, or recovery evidence.

If the deployment itself must be rolled back, restore the latest `worker-deploy-*` Core snapshot and restart Core:

```sh
ssh -t lofason@192.168.1.235 '
set -eu
B=$(ls -1dt /opt/karmo/backups/worker-deploy-* | head -1)
sudo systemctl stop karmo-core.service
sudo rm -rf /opt/karmo/core-service
sudo cp -a "$B/core-service-before" /opt/karmo/core-service
sudo systemctl start karmo-core.service
systemctl is-active karmo-core.service
/usr/local/bin/karmo status
'
```
